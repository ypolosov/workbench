# Разбор источника по слоям

Основание: сверка и размещение вкладов источников (ME.21), виды фреймворков и соразмерность аппарата (E.4, E.4.DPF), записи решений (E.9), запись только того, что меняет будущий выбор (SYSE.43). $WORKBENCH и $FPF - пути из сообщения начала сессии; слои и правило раскладки - раздел 3 `AGENTS.md`. Выполнить по шагам.

## 1. Источник и цель

Назвать источник (файл, папка, стенограммы сессий, заметки памяти, планы) и цель разбора: перенести знание в слои и затем удалить источник или только перенести. Большой источник разбирать частями; части можно отдать нескольким агентам, но свод и проверку делать самому.

## 2. Вклады

Прочитать источник целиком и выписать вклады: правило, соглашение, решение, факт об устройстве, метод, проверка. У каждого - место в источнике (файл:строка или дата и время сессии) и статус: принят владельцем, предложен агентом, отменён позже.

## 3. Сверить с тем, что есть сейчас

Источники стареют и расходятся: решение владельца, журнал решений по ходу работы и код говорят о разном. Каждый вклад о проекте сверить с его текущим состоянием - кодом и конфигурацией рабочей ветки; утверждение действует для конфигурации, с которой сверено (SYSE.13), и её называют. Более позднее решение отменяет раннее, запись несёт обе версии с датами. Решение, которого нет в коде, помечается "решено, в коде пока нет". Несовместимые версии без решения владельца - открытый вопрос владельцу, а не выбор агента (ME.21, силы "сходство и расхождение").

## 4. Вычесть то, что уже есть

Для каждого вклада найти в $FPF (`rg -n`) паттерн, который его уже даёт. Даёт целиком - во фреймворк идёт только ссылка на паттерн; даёт частично - ссылка и местный остаток (ME.21:4.1, шаг 4). Повторы внутри источника и между источниками свести в один вклад, различия, меняющие действие, сохранить.

## 5. Слой

Разложить по правилу раскладки из `AGENTS.md`: личный LPF, личный DPF, проектный LPF, проектный DPF, запись решения своего слоя, память базы, проверка (хук, тест, CI) или отброс. В личные слои - только без данных компании: без названий её систем, хостов, аккаунтов и ключей задач.

## 6. Запись разбора

Таблица "вклад | источник | куда | что осталось или отброшено и почему". Для проекта она ложится в запись решения проекта о разборе, для личного - в карточку РП.

## 7. Показать владельцу

Ничего не переносить и не удалять без подтверждения владельца. После подтверждения: записать вклады в слои, удалить источник, если всё полезное из него ушло. В целевом проекте ничего не сохранять в git без прямой команды владельца.

## 8. Форма

Паттерн фреймворка - по E.8: заголовок `## <ID> - <название>`, шапка с типом и статусом, 12 разделов содержания по порядку и завершающая метка `### <ID>:End` (вместе 13 канонических разделов E.8:4.1). Издание фреймворка - по E.11.PFP: заголовок, оглавление, Readme с практическими входами, предисловие, тела паттернов, источники и условия обновления. Пока фреймворк маленький, он живёт одним файлом (E.4.DPF). Новый паттерн честно помечается семенем, пока не прошёл оценку E.21.
