# Этапы работы

Основание - издание FPF из `$WORKBENCH/.fpf-edition`; тела паттернов искать в `$FPF` по ID.

- **ME.8** (`Engineering DPF Suite/METHOD-ENGINEERING-PRINCIPLES-FRAMEWORK.md`): описание метода пишется для названного использования. Шаг 5 в ME.8:4.1 - каждое нужное действие связать с его входами, выполняемой операцией, результатом и условием продолжения или остановки. Шаг 8 - проверить описание, пройдя по нему маленький случай.
- **A.15.2** (`FPF-Spec.md`): этапы РП - план, то есть намерение. План не выполняет работу и не доказывает её.
- **SYSE.20** (`Engineering DPF Suite/SYSTEMS-ENGINEERING-PRINCIPLES-FRAMEWORK.md`): порядок строк в описании не равен порядку работ. Настоящие зависимости называются, остальное может идти параллельно, возвраты допустимы.
- **OPS.5:4.5** (`Engineering DPF Suite/OPERATIONS-MANAGEMENT-PRINCIPLES-FRAMEWORK.md`): незавершённое уходит с решением - отложено с условием пересмотра, отклонено или возвращено с названным недостающим входом.
- **A.15.5** (`FPF-Spec.md`): перед стадией проверить, что её вход на месте.
- **CHK.1** (`Engineering DPF Suite/CHECKLIST-PRINCIPLES-FRAMEWORK.md`): проверка - короткий набор вопросов, каждый к конкретному упущению.
- **A.15.11** (`FPF-Spec.md`): метод предлагается в том месте работы, где он помогает. Поэтому этапы предлагаются при допуске задачи, а не ждут просьбы.

## Когда

- При допуске новой задачи: предложить этапы для карточки РП или карточки задачи. Маленькой задаче хватит одной строки.
- По просьбе владельца: построить этапы или описание процесса, проверить готовую таблицу.

## Построить

1. **Назвать использование** (ME.8:4.1, шаг 1): кто будет работать по этапам, какой результат нужен и где остановка. Результата нет в запросе - спросить владельца.
2. **Выделить стадии.** Одна стадия - одно действие с проверяемым выходом. Оставить только стадии, без которых результат не получится. Убирая стадию, проверить, не перейдёт ли её работа молча к другому участнику (SYSE.20).
3. **Заполнить таблицу:**

   | Стадия | Вход | Действие | Выход | Условие продолжения |
   |---|---|---|---|---|

   Вход - выходы прошлых стадий; то, что приходит извне, помечается "(внешний)". Условие продолжения - наблюдаемый признак, при котором идти дальше, и что делать, если его нет.
4. **Назвать зависимости** (SYSE.20): чей выход нужен какой стадии. Независимое можно делать параллельно.
5. **Проверить на маленьком случае** (ME.8:4.1, шаг 8): пройти от первого действия по входам и выходам до остановки. Где действие опирается на то, чего нет в таблице, - дописать вход или назвать недостающее.

## Проверить готовое описание

Ответить на вопросы (CHK.1). Каждый ответ - "ОК", "ВНИМАНИЕ" или "НАРУШЕНИЕ" с предложением правки.

1. У каждой стадии есть вход, действие, выход и условие продолжения?
2. Каждый выход кому-то нужен: следующей стадии, результату или следующему кругу? Выход без потребителя лишний, или потребитель пропущен.
3. У каждого входа есть источник: выход прошлой стадии или пометка "(внешний)"? Вход без источника - пропущенная стадия.
4. Каждая стадия нужна результату? Если без неё ничего не сломается, она лишняя.
5. В повторяемом процессе незавершённое уходит с решением и условием пересмотра (OPS.5:4.5), а не просто во вход следующего круга?
6. Описание не выдаёт план за сделанную работу (A.15.2)?

Итог одной строкой; при нарушениях - исправленная таблица.

## Чего не делать

- Не считать таблицу доказательством выполнения: выполнение подтверждает наблюдаемый признак (A.15.1).
- Не раздувать описание: в нём только то, что меняет работу по нему (ME.8:4.1, шаги 3 и 6).
