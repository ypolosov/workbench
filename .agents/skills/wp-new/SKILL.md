# Новый рабочий продукт

Основание: допуск работы по FPF (OPS.5) - задача принимается, откладывается, отклоняется или возвращается; этот скилл оформляет только решение «принять». $WORKBENCH - путь из сообщения начала сессии.

## Шаги

1. **Сначала проверить, нельзя ли продолжить существующий РП** из `$WORKBENCH/docs/WP-REGISTRY.md`. Можно - сказать об этом и не заводить новый.
2. **Предложить формулировку и дождаться явного «да» / «делаем» / «заводи»:**
   - название - существительное-результат по-русски, до 80 символов, без внутренних подробностей целевого проекта;
   - критерий готовности - наблюдаемый признак;
   - оценка в часах.
   Без явного согласия на эту формулировку файлы не создавать.
3. **Номер** N = наибольший номер в реестре + 1 (в пустом реестре - 1).
4. **Карточка** `$WORKBENCH/inbox/WP-N/WP-N.md`:

```markdown
---
wp: N
title: "<название>"
status: in_progress
budget: <X>h
created: <ГГГГ-ММ-ДД>
last_session: <ГГГГ-ММ-ДД>
project: <имя папки целевого проекта>
---

# WP-N: <название>

## Результат и критерий готовности

<что будет и как проверим>

## Этапы

<по желанию: таблица ВДВ «Стадия | Вход | Действие | Выход | Условие продолжения»>

## Осталось

**Что пробовали:** -
**Что узнали:** -
**Что дальше:** <первый шаг>
```

5. **Строка в реестре:** `| N | **<название>** | in_progress | <X>h | inbox/WP-N/WP-N.md |`.
6. **Сказать владельцу:** «Завёл РП N: <название>. Работаю по нему.» Сохранение в git - при закрытии сессии.
