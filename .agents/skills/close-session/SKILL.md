# Закрытие сессии

Основание: короткая запись для продолжения вместо журнала (ME.20), восстановимое состояние работы (OPS.4), запись только того, что меняет будущий выбор (SYSE.43). $WORKBENCH и $FPF - пути из сообщения начала сессии. Выполнить по шагам, ничего не пропуская.

## 1. Итог

Коротко для владельца: что сделано, по какому РП, в каком целевом проекте, что осталось.

## 2. Запись знаний

Пройти по сессии и назвать кандидатов: «Запись: [что] → [куда]».
- Факт о владельце или его способе работы → `$WORKBENCH/memory/` (файл + строка в `MEMORY.md`).
- Правило работы → `$WORKBENCH/lpf/README.md`.
- Личное решение с последствиями → `$WORKBENCH/decisions/` по шаблону.
- Факт о целевом проекте → только в сам проект или во встроенную память агента для этого проекта, не в $WORKBENCH.
Записывать только после подтверждения владельца. Нечего записывать - так и сказать.

## 3. Карточка РП

В `$WORKBENCH/inbox/WP-<N>/WP-<N>.md` обновить раздел «Осталось» (что пробовали, что узнали, что дальше) без кода и данных целевого проекта, поле `last_session` и строку «FPF: издание <коммит из `$WORKBENCH/.fpf-edition`>», если в сессии опирались на FPF. Изменился статус - поправить строку в `$WORKBENCH/docs/WP-REGISTRY.md`.

## 4. Сохранение

- В $WORKBENCH: `git status --short`, застейджить только файлы этой сессии по именам (никогда `git add -A`, `.` или `-u`), `git diff --cached --name-only`, коммит с понятным сообщением. Отправка в удалённое хранилище - по команде владельца.
- В целевом проекте - ничего без прямой команды владельца; назвать, что там осталось несохранённым. Файлы подключения workbench не сохранять.

## 5. Отчёт

Одним сообщением: что сохранено и куда, что осталось, следующий шаг.
