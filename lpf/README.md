# Практика работы workbench (семя LPF)

**Для кого и зачем.** Для владельца и его агента в Claude Code, которые ведут интеллектуальную работу в этой папке. Первый полезный шаг любой сессии - связать задачу с рабочим продуктом (РП) и продолжить с шага, записанного в его карточке. Обычная остановка - закрытие сессии: карточка РП обновлена, знания записаны, изменения сохранены. Неверный поворот - работа без РП или по памяти из чата: вернуться к допуску задачи.

**Статус.** Это локальный чеклист, а не готовый фреймворк. По FPF полезный локальный чеклист остаётся чеклистом, пока у него нет базы источников, тел паттернов, связей и оценки качества (E.4.DPF). Честный статус - семя (seedOnly). Зависимость: ядро FPF и Engineering DPF Suite в закреплённом издании ($WORKBENCH/.fpf-edition).

## Правила и их основания в FPF

| # | Правило | Основание |
|---|---|---|
| 1 | Допуск задачи: принять, отложить с условием пересмотра, отклонить или вернуть с названным недостающим входом. Решение принимает владелец. | OPS.5 Admit Work and Limit Starts |
| 2 | Вход в работу: прочитать "Осталось" в карточке РП, проверить, что всё нужное для шага есть. | A.15.5 Work-Entry Readiness; A.15.10 Resume Interrupted Work |
| 3 | Состояние работы восстанавливается из карточки РП, а не из памяти чата. | OPS.4 Keep Current Operating State Recoverable |
| 4 | План - намерение, работа - сделанное. Запись или сгенерированный файл не доказывает выполнение. | A.15.2 WorkPlan; A.15.1 Work; OPS.6 |
| 5 | Закрытие: короткая запись для продолжения ("что пробовали, что узнали, что дальше"), а не журнал всего подряд. | ME.20; OPS.6 |
| 6 | Знание записывается туда, где оно будет использовано; сначала вычесть то, что уже есть в FPF и DPF. | ME.21; SYSE.43 |
| 7 | Решения с последствиями - в `decisions/` (проблема, решение, почему, последствия, условие пересмотра). | E.9 |
| 8 | Обязательный шаг остаётся, только если он меняет решение или результат либо защищает условие использования. | A.11.OP |

## ВДВ (Вход, Действие, Выход) с поправками FPF

Шесть принципов - в скилле `vdv` (взят из IWE; значки вердикта заменены словами). При использовании учитывать:

1. **Порядок стадий в описании не равен порядку работ.** Независимые действия могут идти параллельно, возвраты допустимы (SYSE.20).
2. **К триаде добавить условие продолжения или остановки** для каждой стадии (ME.8).
3. **Незавершённое переносить вместе с условием пересмотра**, а не просто во вход следующей итерации (OPS.5, решение "отложено").
4. **Антипустышка:** убирая стадию, проверить, не переложится ли её бремя на другого участника (SYSE.20).
5. Таблица ВДВ описывает метод, а не доказывает, что работа выполнена (A.15.1).

## Что дальше

После недели работы переносить правила по одному в паттерны формы FPF (E.8: 13 разделов, заголовок `##`, маркер `### <ID>:End`) по маршруту E.4.DPF. Порядок: открытие и закрытие, допуск РП, ВДВ, запись знаний. Проверка по чеклисту - основа Checklist DPF (CHK.1-CHK.6). Решение "это LPF или набор чеклистов" записать в `decisions/`.
